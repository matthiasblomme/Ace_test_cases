# testing

Harness for `RCDInvalidCharRepro`. One topology only.

```
testing/
  test-resources/
    make-test-data.ps1        generates the fixtures byte-exactly
    input/
      clean-order.xml         schema-valid, no control characters
      dirty-order.xml         same document with a literal 0x1A (generated, not committed as text)
      bad-order.xml           well-formed, carries an element the schema does not declare
      per-path/               one input file per branch, named after the harness label,
                              with a README mapping file -> URL -> expected result
  standalone-server/
    run-test-with-ace-env.bat sources mqsiprofile, then calls the harness
    deploy_and_test.bat       the harness
    stop_server.bat
    README.md                 prerequisites, config table, expected results, troubleshooting
    results/                  captured output, overwritten each run
```

Start here: [standalone-server/README.md](standalone-server/README.md).

Run it with:

```
testing\standalone-server\run-test-with-ace-env.bat -fresh
```

## Fixtures

`dirty-order.xml` carries a literal `0x1A` (SUB) inside the `Description` element
content. It is generated by `make-test-data.ps1` rather than committed, because the
byte is invisible in an editor and most tooling strips or re-encodes it on save. If
the fixtures ever look wrong, regenerate:

```
powershell -File testing\test-resources\make-test-data.ps1
```

The script prints the byte count and whether `0x1A` is present, so a broken fixture
is visible immediately rather than showing up as a mysterious passing test.

No queue manager, no policy projects, no third-party jars, no shared-classes. The
only external dependency is an ACE 13 installation.
